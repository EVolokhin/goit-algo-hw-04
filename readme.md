## 2. Емпірична перевірка теоретичної складності та ефективності Timsort

Емпіричні дані повністю підтвердили теоретичні викладки щодо часової складності:
* **Сортування вставками** демонструє квадратичне зростання часу (O(n^2)), через що воно стає практично непридатним для роботи з великими масивами даних.
* **Сортування злиттям** показує стабільну логарифмічну складність (O(n \log n)), чудово справляючись із великими масивами, проте програє за рахунок накладних витрат на рекурсію та створення нових списків на чистому Python.
* **Timsort** поєднує найкращі риси обох підходів: він використовує сортування вставками для мінімальних локальних послідовностей (runs) та злиття для їх об'єднання. Це забезпечує йому неперевершену швидкість та адаптивність (на вже відсортованих даних час прямує до лінійного O(n)).

---

## 3. Висновки щодо ефективності алгоритмів

1. **Гібридний підхід є ключем до швидкодії:** Поєднання сортування вставками та злиттям у Timsort робить його надзвичайно ефективним для реальних даних, які часто містять частково впорядковані фрагменти.
2. **Перевага низькорівневих оптимізацій:** Вбудовані функції сортування Python (`sorted()` та `.sort()`) реалізовані на мові C, що додатково знижує накладні витрати на інтерпретацію.
3. **Доцільність використання вбудованих засобів:** Програмісти у переважній більшості випадків використовують вбудовані алгоритми Python, оскільки самостійно написати настільки оптимізоване рішення на чистому Python недоцільно ані за витратами часу, ані за продуктивністю.
